# skilleval — Phase 0 harness (Option A)

Evaluation harness for the seven pipeline skills (orchestrator, stats-agent,
anomaly-agent, root-cause-agent, explorer-agent, trace-agent, narrator).

**Governing principle:** an answer is *correct* iff it faithfully reports what
the underlying data computes. Ground truth is recomputed from the eval dataset
(never a hardcoded string), so swapping the dataset recomputes the expected
answers. Questions are stored as **paraphrase families**, and phrasing
robustness (variance across a family) is itself a scored metric.

## Fixed eval dataset

`backend/datasets/021587a2-59bf-4e73-a85e-97905f790841.json`
(2070 action rows, 14496 widget rows, real timestamps). Chosen because it is a
full snapshot with `action_duration_ms` already normalized.

**Source CSV (confirmed by fingerprint):** `~/Downloads/data (82) (2).csv` — a
raw long-format SAP export (35 columns, 45590 data rows). Parsing it with the
app's `parseCsv.js` config and running the full ActionView pipeline reproduces
the dataset exactly: 2070 actions / 14496 widget rows / worst action
"Open story" (dur 10368063 ms). `groundtruth_gen.mjs` asserts this fingerprint.

## Ground-truth strategy (decided after source investigation)

An answer is correct iff it matches what the tool's OWN code computes. So ground
truth is generated by running the actual `src/lib` functions (`kpis.js`,
`anomalyDetect.js`, `buildAgentPayload.js`, `storyActionMatrix.js`, …) via Node
against the fixed dataset, and freezing the result. Python does not re-implement
any formula — it reads the frozen JSON. This also yields a real `payload.json`
to drive headless rollouts without a browser.

### Validated ground-truth values (fixed dataset, sanity-checked in Python)
- Stats: n=2047 finite / 2070; median 4628ms, p90 22847ms, p95 41229ms; over-`120000`ms (inclusive `>=`) = **47**.
- Trace: worst action "Open story" → bottleneck widget **"Image"**, dominant phase **render**.
- Percentile method: linear interpolation, inclusive (`rank=p*(n-1)`), over per-action `action_duration`.

### Known caveats baked into the benchmark
- `explorer-busiest-hour`: the tool has **no hour-of-day computation** (it buckets by absolute hour). This entry will likely baseline near zero for reasons that are a *capability gap*, not a skill-prompt defect — it documents the gap that the `quizzical-wobbling-sedgewick` plan fills. Ground truth defined as the absolute-hour bucket with the most actions.
- `trace-*`: the "worst action" (max `action_duration`) is a ~2.9h outlier whose bottleneck is ~0% of the action. The `widget_name`/`dominant_phase` answers are still well-defined and agent/ground-truth agree on the action, so scoring is consistent.
- Anomaly derived fields (`active_headline_types`) aren't emitted by the detector directly; ground truth = headline types with count>0.

## Open item (blocking rollouts, not ground truth)
Whether each agent echoes the precomputed `payload` or recomputes from mesh rows
— determines the minimal `payload` needed to run a rollout end-to-end. Question
is out to the rollout-mechanism investigation.

## Scoring (approved)

Per rollout, weighted 0–1:
- Answer correctness **0.50** — agent-specific fields vs recomputed truth, within tolerance
- Routing **0.20** — right agent invoked for this question
- Schema validity **0.15** — required contract fields present and typed
- Guardrails / no leakage **0.15** — e.g. trace-agent emits no KPI values; `session_notes` present

Tolerances: counts exact; percentiles/durations ±0.5% relative; pct fields ±1pp.
Aggregate: mean over reps (≥5), then mean **and variance** over the paraphrase
family (variance = brittleness). Fuzzy fields (root-cause prose, narrator
headline) use a light LLM judge; everything else is deterministic.
